# Multiple senders to one Android receiver

The previous one-sender/multiple-receiver proposal was based on a misunderstood direction and is withdrawn. The user confirmed simultaneous **multiple senders -> one receiver -> mixed output**, and has authorized implementation.

Use the same receiver flow for one or multiple sources, with a source list and independent volume/mute/disconnect and latency choices. Prefer Android per-source AudioTrack/system mixing, one foreground service/notification, bounded session count and PCM queues. Each source owns its authentication, transport, metrics, clock correction and retry intent. One source failing must not stop the other sources. Retain WFAS v2 framing and compatible existing senders.

Runtime fixes precede feature acceptance: reliable metrics and playback-health classification, partial-write continuity and burst bounds, privileged capture setup/cleanup, network-specific sockets and offline waiting. Mixed gain must stay within unity for app-owned streams and change smoothly. Manual user stop/removal cancels persisted reconnect intent. Existing single-target settings migrate without changing the saved manual buffer preference.

Work item: [android-multisource-recovery](../work-items/android-multisource-recovery.md). Device details and raw incident evidence stay local and ignored. Test preview uses the permanent signer and independent applicationId; original test16 is retained. Actual long-run/OEM/VPN and capture-route acceptance remain open until measured.
