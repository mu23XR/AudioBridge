# AudioBridge 1.3.1-test.19 preview

Android supports up to four simultaneous WFAS sender sources into one receiver
with system mixing, source volume/mute/disconnect, independent adaptive or
continuous manual buffer settings, and one foreground host. Individual source
failure does not intentionally close the other sources. Existing v2 senders
keep their single-receiver contract.

Receiver changes preserve partial PCM write tails in a duration-bounded queue,
separate UDP/control from playback, correct silence sequence metrics and
playback-head wrap accounting, and verify actual rate-change results. Route
selection is per socket, offline reconnect waits, and privilege-scoped capture
setup restores Binder identity and passes shell attribution to the actual
recorder builder. Capture startup retries are bounded and failure notifications
give a readable operation summary with details retained in app state/logs.

The permanent-signed independent .test package coexists with test16/stable.
This build request is artifact-only, not a stable release. No signing-key or
wire-format migration. Unrelated Desktop development is not included.

Unit/lint/build, loopback multi-source and supported real-device capture
acceptance are tracked in docs/work-items/android-multisource-recovery.md.
Actual prolonged listening, OEM power termination and all VPN/Bluetooth
combinations remain acceptance boundaries; green builds do not close them.
