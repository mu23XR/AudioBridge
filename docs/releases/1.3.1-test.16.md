# AudioBridge 1.3.1-test.16

基于最新开发版本（2caa437，包含 test.14 后的 Desktop 赞助计时器清理），保留 test.13 后的功能与清理。

## 保留的新行为

- 通知栏再次点击发送会重新启动发送，再次点击接收会重新连接，关闭可以重复执行完整清理。
- 保留已删除的原作者窗口、赞助入口、自动弹窗和产品网站链接的清理结果。
- 普通连接超时显示状态文字，协议不兼容仍给出明确提示。
- 二维码使用 AudioBridge 自己的 `audiobridge://pair` 格式。建议两端同时升级并重新生成二维码。

## test.15 真机验收后的修正

- test.15 在平板上发现启动静音同步会改变外放音量，本版去掉显式 UNMUTE 和最大音量设置，改用已观察有效的一次音量加动作；音量快照提前到 AudioPolicy 尝试前。真机仍需复验。

## 本版修复

- Shizuku REMOTE_SUBMIX 发送建立虚拟路由后同步系统媒体静音，避免外放音量为零时启动发送必须再按音量键；原外放音量索引不提高。
- 持续零 PCM 改为无音频负载的保活包，避免接收端系统把长期零音频播放暂停。
- Android 接收播放使用非阻塞写入，缓冲只统计真正接收的帧；播放停滞时恢复轨道，收包与心跳不再等待阻塞播放。
- 重连的旧任务只清理自己，不覆盖新连接状态；快速 SEND/OFF/RECEIVE 取消过期的待启动命令。
- HTTP 关闭先释放监听端口，再清空引用。
- 修复 Desktop Snapcast 连续音量命令的旧确认覆盖新值；短时间过滤已被替代命令的回包。
- 修复 Desktop 协议测试名称冲突并将协议自检纳入检查；移除正式发布 YAML 的重复残留。

## 验证与限制

这是预发布测试版。CI 必须完成 Android 单元测试、编译、签名验证、Windows 检查/打包和项目治理检查才发布。

静音至少三分钟后恢复、零外放音量启动发送、反复清后台、锁屏、快速角色切换等真机验收仍需要在此构建上执行。清后台路径保留今天已观察到有效的 owner-death/同步释放实现，不宣称所有机型问题已解决。

Android 包名和永久签名不变，可直接覆盖升级 test.13/test.14，保留设置。WFAS 仍为 v2，无音频线协议变更。不要卸载旧永久包。

APK、Windows 包、`SHA256SUMS.txt` 和 `SOURCE_COMMIT.txt` 随本次发布提供。
