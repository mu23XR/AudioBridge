# AudioBridge 1.3.1-test.20

Independent preview for reception recovery, selectable sender playback and synchronized transmission volume. The Android package is `io.github.mu23xr.audiobridge.test`, signed with the existing permanent certificate; it upgrades test19 without removing the stable-package test16. CI publishes this as a prerelease, never latest stable.

- Receiver network selection compares managed and directly attached interfaces and respects scoped IPv6/interface selection. UDP replies are inspected with explicit peer validation and bounded endpoint diagnostics. Retry observers can no longer bypass backoff; cancelled handshakes are not mislabeled ACK timeouts.
- Ordinary service destruction preserves selected running mode. Actual Stop/Recents removal retains shutdown and route cleanup. OEM force-stop remains an external limitation.
- Shizuku sending offers remembered local playback or remote-only playback. Stop sending before changing mode. Remote-only exposes transmission volume through a volume media session without requesting audio focus; system/OEM arbitration with other media apps still requires physical-device acceptance. An explicitly requested local-playback route fails clearly if unsupported.
- Transmission volume displays 0–100: 50 is unity, 100 is the former gain-2 ceiling. UI, notifications, overlay and key controls use the same mapping. Sender and receiver master gain are remembered on changes.
- New Android peers negotiate optional sender-volume control, query initial state and acknowledge ordered changes. Receiver local master/mix controls remain separate; old peers continue audio and show remote volume unsupported. Key-authenticated sessions authenticate these controls and reject replay.
- Playback recovery and queue discontinuities apply a complete fade across short/partial/zero writes. Above-unity transmission peaks use soft compression instead of hard clipping; this can alter timbre and is not lossless amplification. Unity keeps PCM unchanged.
- Diagnostics distinguish no-data reads, silent PCM, potential clipping, peak processing and output/network recovery. Authorized ADB shell can export the redacted bundle without opening device screens; journals stay private and ordinary callers are denied.

Validation results and remaining acceptance are tracked in `docs/work-items/android-test20-reception-volume.md`. Compilation, unit tests and quiet loopback fixtures do not establish the historical ACK root cause, cross-device volume-key behavior or overnight sound quality. Preserve test16 as the rollback option while testing this preview.
